# Feature Workflows

## Discover → Search → Learn → Practice → Build → Track → Review

This document explains how the major parts of Charlie MJ DevOps Explorer connect.

## 1. Discover

Start from Dashboard, Taxonomy, Technologies, or the popup.

Choose a DevOps area such as:

- Cloud
- CI/CD
- Containers
- Kubernetes
- Infrastructure as Code
- Security
- Monitoring
- Networking
- Databases

## 2. Search

Use local search to discover resources already available in the extension.

Use GitHub Search when you need live repository discovery.

## 3. Capture

Save useful results as:

- Bookmark
- Favorite
- Collection item
- Tagged resource
- Labeled resource

## 4. Learn

Turn the resource into a Learning card.

A Learning card becomes the central learning object connecting reference material and practical work.

## 5. Official documentation

Attach one or more official documentation records to the Learning card.

This prevents the Learning card from depending only on third-party articles or videos.

## 6. Practice with Labs

Create or select a Lab that demonstrates the concept.

Example:

```text
Learning: Amazon EKS Fundamentals
        ↓
Lab: Deploy a sample application to EKS
```

## 7. Build with Projects

A Project represents a larger outcome.

```text
Learning: Kubernetes Networking
        ↓
Project: AWS EKS DevOps Platform
```

## 8. Track with Goals

Goals define why you are learning something.

```text
Goal: Become comfortable deploying Kubernetes workloads
        ↓
Learning cards + Labs + Projects
```

## 9. Plan with Roadmaps

Roadmaps organize a sequence of learning topics.

```text
Linux → Git → Docker → Kubernetes → AWS → Terraform → CI/CD
```

Individual Learning cards can be attached to the relevant Roadmap.

## 10. Review

Use:

- progress
- status
- activity
- notes
- favorites
- collections
- goals

for continuous review.

## 11. Documentation workflow

```text
Technology
   ↓
Category / Subcategory
   ↓
Official Documentation
   ↓
Health Check
   ↓
Learning Card
```

## 12. Import/export workflow

Use JSON when you need structured portability.

Use Markdown when you need human-readable knowledge documents.

```text
Workspace
   ↓
Export JSON / Markdown
   ↓
Git / backup / notes / knowledge base
   ↓
Import later
```

## 13. Recommended personal DevOps workflow

1. Search a technology.
2. Inspect official documentation.
3. Search GitHub for examples.
4. Bookmark strong repositories.
5. Create a Learning card.
6. Add official documentation.
7. Add a Lab.
8. Add or create a Project.
9. Link the Learning card to a Goal.
10. Place it in a Roadmap.
11. Track progress.
12. Export Markdown for your external notes.
